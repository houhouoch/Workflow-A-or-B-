## AI 执行契约

当 AI 被要求执行任意一套流程时，应遵循：

1. 读取本知识库和目标工程本地说明。
2. 检查 Git 状态，保护无关的用户改动。
3. 识别真实工程文件、AXF、芯片目标、探针 UID 和串口日志路径。
4. 先预检，再编译，再下载，最后调试。
5. 优先使用命令行和官方 API，不使用鼠标坐标自动化。
6. 下载没有短超时，必须等到完整校验标志。
7. 从日志中提取断点、源行、调用栈或表达式证据。
8. 不把“已连接”“程序退出码为零”描述成完整成功。
9. 释放所有私有调试进程。
10. 只报告实际执行并验证过的结果。

## 新电脑最小清单

- [ ] Keil MDK 能手动打开并编译目标 `.uvprojx`。
- [ ] `UV4.exe`、`UVSC64.dll` 和工程所需编译器存在。
- [ ] Python 3 可从 PowerShell 运行。
- [ ] 流程 B 所需 pyOCD 和 `arm-none-eabi-gdb` 可运行。
- [ ] CMSIS-DAP 能发现目标板。
- [ ] 只有一个程序占用探针。
- [ ] 编译日志为零错误。
- [ ] 下载出现三个完整校验标志。
- [ ] 流程 A 能命中一个硬件执行断点。
- [ ] 流程 B 能输出匹配的 `#0` 栈帧。
- [ ] 目标继续运行后串口出现新的启动日志。
- [ ] 调试退出后没有遗留私有进程。

## 推荐验证阶梯

```text
环境检查
  -> 只编译
  -> 只下载
  -> 周期性函数断点
  -> 启动函数断点
  -> 表达式/调用栈读取
  -> 串口端到端验证
```

不要在第一步就运行完整链路。分层验证能快速定位错误归属，也便于另一台电脑复现。
