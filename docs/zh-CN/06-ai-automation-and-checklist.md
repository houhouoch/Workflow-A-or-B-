## AI 执行契约

当 AI 被要求执行任意流程时，应遵循：

1. 读取本知识库和目标工程本地说明。
2. 检查 Git 状态，保护无关的用户改动。
3. 识别真实工程文件、AXF/ELF、芯片目标、探针 UID 和串口日志路径。
4. 先预检，再编译，再下载，最后调试。
5. 优先使用命令行和官方 API，不使用鼠标坐标自动化。
6. 下载没有短超时，必须等到完整校验标志。
7. 从日志中提取断点、源行、调用栈或表达式证据。
8. 不把“已连接”“程序退出码为零”描述成完整成功。
9. 释放所有私有调试进程。
10. 只报告实际执行并验证过的结果。

## 流程 A / B：新电脑最小清单

- [ ] Keil MDK 能手动打开并编译目标 `.uvprojx`。
- [ ] `UV4.exe`、`UVSC64.dll` 和工程所需编译器存在。
- [ ] Python 3 可从 PowerShell 运行。
- [ ] 流程 B 所需 pyOCD 和 `arm-none-eabi-gdb` 可运行。
- [ ] CMSIS-DAP 能发现目标板。
- [ ] 只有一个程序占用探针。
- [ ] 编译日志为零错误。
- [ ] 下载出现三个完整校验标志。
- [ ] 流程 A 能命中一个硬件执行断点。
- [ ] 流程 B 能输出匹配的 `#0` 栈帧。
- [ ] 目标继续运行后串口出现新的启动日志。
- [ ] 调试退出后没有遗留私有进程。

## 推荐验证阶梯

```text
环境检查
  -> 只编译
  -> 只下载
  -> 周期性函数断点
  -> 启动函数断点
  -> 表达式/调用栈读取
  -> 串口端到端验证
```

不要在第一步就运行完整链路。分层验证能快速定位错误归属，也便于另一台电脑复现。

## 流程 C：新电脑最小清单

- [ ] CMake、Ninja、完整 GNU Arm 工具链、Python 和 pyserial 可运行。
- [ ] SEGGER 动态库可用，pyOCD 能枚举本次 J-Link UID。
- [ ] Device Pack、run description、QSPI FLM 和看门狗脚本属于本次目标工程。
- [ ] 输出 OFF、List 停止；用户已确认暂停/复位条件。
- [ ] 架构检查、主机测试、Release 编译和镜像预检通过。
- [ ] 烧录前备份保留；APP/ELF 不被其他构建覆盖。
- [ ] 全量回读长度与 SHA-256 一致，CPU/Tick 与向量表正常。
- [ ] 本次探针 VCOM 已启用，端口正确；115200、8N1、无流控。
- [ ] 采集先于复位，只读且 DTR/RTS 关闭；收到新的启动与完成标志。
- [ ] 采集退出后串口释放，没有私有调试进程残留。
- [ ] 源码调试要求真实断点、单步、参数与调用者证据；RTT、RTOS 与跟踪功能分别验收。

步骤与当前验收状态见[流程 C](07-workflow-c-macos-jlink.md)。此清单不自动授权开启电源输出或修改固件行为。
